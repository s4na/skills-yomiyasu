# PR5：同じ評価対象への採点の矛盾を検出する

## 問題と採否

3種類のプロンプトを比較したが、すべて不採用とする。最後の候補Cは調整11件で採点2名とも満点だった。しかし独立レビューで、失敗判定されたBと全文同一の出力が見つかった。満点を改善の根拠にはできない。スキル本体はPR4と同じ690バイトを維持する。

必要だった変更は、文章ルールの追加ではなく評価結果の照合である。`tools/summarize_scores.py` は、rubric・依頼・原文・checks・出力が完全一致する採点をまとめ、critical項目1〜4の合否が混在する組を `disputed` と表示する。候補名や匿名IDは同一性の判定に使わない。多数決や採点の書き換えは行わない。

## プロンプト実験の原票

毎回新規の実行役と採点役2名を使い、採点の提示順を反転した。固定基準6項目は変更していない。以下は**採点原票から数えた合格数であり、意味保持を独立に確認した成功数ではない**。

| 試行 | 対象 | 現行版 | 候補 | 判断 |
| --- | --- | --- | --- | --- |
| A：照合指示を短縮 | 調整8件 | 8/8 | 8/8 | 下記の見落としあり |
| A：当初の未使用集合 | 3件 | 2/3 | 2/3 | 不採用、集合を調整用へ移した |
| B：読み方を事前確認 | 調整11件 | 10/11 | 10/11 | 条件の限定が残り不採用 |
| C：必要な変更だけ行う | 調整11件 | 10/11 | 11/11 | 同一出力の採点矛盾により不採用 |
| C：新しい未使用集合 | 3件 | 3/3 | 3/3 | 調整側の失敗を相殺しない |

予備確認では、引用・コード・部分編集・JSON形式の6件、3537字の技術報告を含む長文3件、複雑な文3件が原票上合格した。長文3件では最小プロンプトも合格したため、長さだけを理由に処理段階を追加する根拠にはならなかった。

## 独立レビューで判明した失敗

Cの実行643とBのe93の `4db-02` は全文一致する。原文の「同じ日に続けて予約を分けても」を「同じ日に連続する時間帯を分けて予約しても」に変えている。「続けて」が予約行為を修飾する読みを除き、利用時間帯の連続へ限定している。

Bの採点88f・afbは項目2・3を0.5、Cのe98・9c2は同じ評価資料に全項目1を付けた。この矛盾があるため、Cの11/11を採用根拠から撤回した。Cと比較した現行版768にも同種の限定が残る。試行によって予約条件の失敗が消えた、とは判断しない。

またAの752・ae3には「利用者に」という原文にない主体の補足があり、満点の原票はこれを見落としている。C比較の現行版768では同種の補足が減点された。これは表現が異なるため、今回の完全一致検出だけでは拾えず、人による意味の確認が必要である。

AのD6では主担当が確認質問の前提を疑い、同じ基準でこの1件を新規2名に追加採点させた。両名とも合格した。全記録を残し、独立した改善の証拠には数えない。読みやすさは原票上すべて1だったが、意味保持の失敗を相殺しない。

## 検出処理の実測

PR4の記録検査は入力・出力・採点の対応と形式を検証できたが、同じ内容への相反する採点は検出しなかった。新しい処理は01〜05の115種類の完全一致資料を集約し、原票上pass 106組、fail 6組、disputed 3組を出力した。この単位はケース数や独立標本数ではない。

3組はPR1のD2、PR3の主体補足、今回の予約条件である。前2組は既存記録でも不一致を説明していた。今回の処理はそれらも機械的に再現する。全員が誤採点した組はpassとなるため、passは正しさの証明ではない。項目5〜6の差も表示するがcritical判定とは分ける。

再現コマンド：

```sh
python3 tools/check_records.py
python3 -m unittest discover -s tools -p 'test_*.py'
python3 tools/summarize_scores.py
```

標準ライブラリのみを使い、スキル実行時には読み込まない。完全一致する実記録の回帰テストと、checks・出力の異なる資料を混ぜないテストを追加した。原票を変更しないため過去の採否も自動で書き換えない。
