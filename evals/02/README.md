# PR2：手順を短くして再検証

## 問題・仮説

PR1では読みやすさの得点が全条件で同じだった。語順・文の区切り・重複の列挙や、照合の手順を指示に残す必要があるかは未確認だった。empirical-prompt-tuningの方法で、この部分を省いても必要な結果が得られるかを調べた。

固定基準の1〜4を維持しながら、指示量を減らす仮説。品質向上や高速化の仮説ではない。調整用は以前の6件に引用・部分編集・コードを加えた9件。未使用3件は別担当が作成し、候補固定後に開封した。

## 変更と結果

指示を1段落にまとめ、具体的な操作の列挙と独立した照合手順を削除した。意味保持、不明点の不補完、修正不要の文章の保持、出力形式は残した。

| 指標 | PR1版 | 短縮版 |
| --- | ---: | ---: |
| スキル全体のUTF-8バイト数 | 740 | 469 |
| 見出し後の指示文字数（改行を含む） | 177 | 84 |
| 調整用・critical合格（採点者1 / 2） | 9/9 / 9/9 | 9/9 / 9/9 |
| 未使用・critical合格（採点者1 / 2） | 3/3 / 3/3 | 3/3 / 3/3 |

全件で両採点者の6項目が1。検出された回帰はない。バイト数は実ファイルの測定で、トークン数や実行時間の代わりではない。

短縮版を採用。実行用の段階・スクリプト・依存は増やさない。PR1のD6では差が出たが、今回の再実行ではPR1版も通った。1回の差から安定した性能差は主張できない。
