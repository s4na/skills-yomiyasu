# Issue / Cause / General Fix Rule

## Issue

再評価の状況共有ケースで、目的文を統合した候補出力の一例が「不具合が再現したため、再テスト時間を確保します」となった。原文では「修正後に再テストする時間を確保するため」が延期決定の目的だが、改稿では直近の「再現した」に理由を結び付け、さらに目的を将来の実行約束として読める形にした。採点者1名は固定critical要件をpartialとし、もう1名も実行約束に寄る点を記録した。

## Cause

文どうしを統合する際に、目的節が文章地図上でどの判断・行為を修飾するかを保たず、最寄りの述語に接続し直した。最終照合も、事実単位は残っているが「何の理由か」という関係の変化を捉え損ねた。

## General Fix Rule

離れた理由・目的節を統合するときは、文章地図で係り先となる判断や行為を特定してから語順や接続を変える。近接する述語への機械的な接続で関係が入れ替わるなら統合しない。複数の係り先が残る場合は、元の位置関係を保つか確認する。

## 変更と確認

この一般則を「診断から編集へ」に追加した。初回holdoutは消費済みとして再利用せず、別の題材で新しいholdoutを候補変更前に固定した。新holdoutでは目的節の係り先と案内条件の範囲を両採点者が合格と判定した。結果は [`run-03/README.md`](run-03/README.md) を参照。

## 調整用ケースの回帰

修正した候補を初回の調整用ケースでも別の実行役が1回実行した。目的節を延期の決定に直接係らせ、依頼されていない実行確約に置き換えていない。詳細な出力は [`run-04`](run-04/) に保存。新holdout結果とは分けて扱う。
