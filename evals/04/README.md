# PR4：採点記録と実行出力の対応を検査する

## 問題と仮説

PR3では単独採点が意味変更を見逃した。採点内容の再確認に必要な記録を独立に監査すると、ラウンドのmanifestと採点responseを削除しても検査が成功した。また、採点パケットのoutputだけを別文に置き換えてハッシュを更新しても成功した。ハッシュだけでは記録間の対応を保証できない。

ラウンドの存在、ファイル一覧、実行と採点のID、匿名aliasと実行出力を照合すれば、欠落・転記ミスを検出できると考えた。推敲スキルの実行工程や依存は増やさず、記録検証の標準ライブラリスクリプトを変更した。

## 実測

同じ5テストを直前commitの検査器と変更後に実行した。完全な記録と固定protocol検査は両方成功。manifest欠落、別文への差し替え、採点1件欠落は、直前版では検出できず3テスト失敗、変更後は全5テスト成功。差し替えテストはmanifestを再計算するため、既存のハッシュ検査だけでは不整合を検出できない。[結果](validation.json)

保存済みのPR1〜3全パケットも照合に成功した。採点6項目の値域と件数を確認するが、日本語の正しさを自動判定するものではない。記録一式を整合するよう改ざんした場合やラウンドのディレクトリ全体を削除した場合の検出は対象外。Git履歴とレビューで確認する。

## 不採用の推敲候補

PR3の次課題として、照合の条件を「長文では」から「直した箇所は」へ変え、短文6件で比較した。現行690バイト、候補669バイト。新規実行役2名と提示順反転の新規採点役2名による結果は両方6/6、全6項目が1だった。主体・係り受けが曖昧な文は両方とも保持した。自己報告の不明点も両方に残った。

この21バイトの短縮だけでは採用根拠が弱いため不採用とし、ホールドアウトは実行していない。スキル本体はPR3のまま。品質改善として計上しない。[入力](development.json) / [条件対応](metadata.json) / [起動指示](dispatch.json)
