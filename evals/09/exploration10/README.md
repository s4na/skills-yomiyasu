# 原文・改稿案の不足確認に関する探索

必要な情報が欠けた依頼に対して追加指示が必要か、現行版を新規調整4件で確認した。[事前計画](plan.md)。ケースごとに新規実行役を起動し、2名の新規採点役が単一条件の4件を同じ順序で固定rubricとchecksに基づき採点した（条件間の主観比較なし）。両採点役とも4件全項目1だったため、この試行範囲では不足確認の追加指示を作らないと判断した。

候補は作成せず、正式なホールドアウト評価も実施していない。未使用集合の内容は公開せず、SHA-256だけを[audit.json](audit.json)に保存した。これは品質改善の記録ではなく、追加変更の必要性を調べた探索記録である。主要な採点集計の対象外とし、親ディレクトリのmanifestによるファイルハッシュ検査のみを行う。

各実行役のrequest.json・response.txt・report.json、各採点役のrequest.json・response.jsonを保存した。採点資料は探索当時の原文・依頼・checks・出力を含み、別欄のdraftは含まない。dispatch.jsonは実送信wrapperの事後再構成であり、独立した実行証明ではない。4実行＋2採点の6起動、fork_turns:none、モデル指定なし。共有FSは指示による読み取り制限であり、OSの強制隔離ではない。小標本であり、時間・料金・トークン数は未測定。
