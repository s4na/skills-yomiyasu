# 依頼を揃えた参照比較の再実行

## 条件

- 固定ケース: [`../scenario.json`](../scenario.json)、SHA-256 `63a7f83d1bc9f09cc4af2ed3273fde77a4a0ee6a7af7715bc59ab9be77a8c579`
- 参照: `nanaism/yomiyasu` v2.0.1、commit `84e1f5b15e497538fcfe19ab7e9c6f6d138f19ff`
- 候補: [`../run-01/candidate-SKILL.md`](../run-01/candidate-SKILL.md)、SHA-256 `dec71fb56d51527eca6832042dfeac891872174b53e7c28b829f89ada3973ece`
- 参照と候補の両方に同一のユーザー依頼と原文を渡した。参照は原文lint、`run --stdin --fact-gaps`、提出直前のverifyを各1回行い、3コマンド全て終了コード0。`--doc-type` と `--stance` はタスクから確定できないため省略。詳細なstdout、stderr、コマンド、検査結果は参照出力JSONに保存
- 参照と候補の実行を別々に行い、新しい採点者2名が匿名A/Bを順序反転して採点。採点1はA=候補・B=参照、採点2はA=参照・B=候補
- 採点1は両出力の全要件を合格とし、参照の出力をわずかに滑らかと評価。採点2は両出力の全要件を合格とし、同等と評価した。差は読点のみで、採点者間で優位の合意はない
- 実行モデル名、tool_uses、duration_msは取得できずN/A

## 解釈

この1ケースでは、候補・参照とも不自然な「連絡を行います」を「連絡します」に直し、依頼された本文のみを返した。候補の優位性は示されていない。修正前候補もこのケースでは正しく動いており、変更は編集許可の記述を明確にしたものとして評価する。合成した1ケースから一般性能や利用者満足度は主張しない。
